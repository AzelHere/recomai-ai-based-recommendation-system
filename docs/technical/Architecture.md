# Architecture
Recom AI is a Java 21 Spring Boot 4.1.1 monolith. Spring MVC serves REST endpoints and the static HTML/CSS/vanilla JavaScript frontend from the same origin. Three.js provides optional decorative interactions with reduced-motion and hidden-tab suspension. It never decides recommendations. Controllers use services for validation, ownership and transactions; Spring JDBC DAOs issue parameterized MySQL statements. Flyway applies V1–V18 at startup. Cached immutable TF-IDF vectors enrich real catalog candidate signals before deterministic weighted ranking and bounded diversity selection.

Registration and login replace any prior session and store user identity, role and auth version server-side. Every protected request rechecks persisted identity and authorization. Saved resources, collections, completion, activity and journeys remain owner-scoped. Export/reset/deletion are explicit user operations. There is no JWT, Redis, external vector database or paid AI API. A single instance is the intended first deployment; multiple replicas would need deliberately shared session/rate state and cache invalidation coordination.

The administrative ingestion path is separate from normal browsing. A Java acquisition CLI accesses reviewed official sources with bounded HTTPS/DNS/redirect/byte/time controls, stages normalized JSON and attribution, then an authenticated admin previews and commits bounded batches. MySQL stores accepted identities/provenance and holds uncertain editions for review. An imported resource is a metadata link, not locally hosted course content. Ordinary recommendation requests do not contact providers. Scheduled URL maintenance remains disabled by default; manual checks respect source policy.

LearningJourneyService snapshots goal/topic and selected order in a transaction, stores steps and explicit statuses, preserves completed steps and replaces only unavailable work. Ordering is not a verified prerequisite graph. Recommendation feedback and explicit completion have different semantics. The browser module owns fetch/render state and clears stale results when filters or accounts change.

Local Compose exposes app:8080, MySQL:3307 and Mailpit:8025 only on loopback. The production overlay activates strict secure cookies, authenticated STARTTLS SMTP, an HTTPS origin guard, no database host port, non-root/read-only application execution, dropped capabilities and bounded memory. Public HTTPS termination, certificates, off-host backups and real SMTP remain operator work. The deployment diagram labels this public topology as proposed.
