# Recom AI security verification

The final application image was scanned by Trivy 0.76.2 using the same refreshed 26 November 2026 vulnerability database as the baseline comparison. The evidence includes immutable image identities and complete scanner JSON. Baseline: 161 package/advisory matches (149 medium, 12 low), 67 unique advisory IDs. After compatible Ubuntu runtime security updates: 75 matches (63 medium, 12 low), 38 unique IDs. Both scans have zero critical/high matches. These are package/advisory matches, not 75 distinct CVEs. The final scan lists no remaining available fixed versions.

The runtime still uses the pinned Temurin Java 21 base and the same OS release. `apt-get upgrade` applies available compatible runtime packages during image construction. Rebuild and rescan when new patches become available; a pinned base alone does not imply patched OS packages. Medium/low findings remain accepted residual exposure pending upstream fixes, not proven non-exploitable. Local use does not constitute production security clearance.

Fresh OSV queries checked all 95 resolved Maven dependency versions and found no known advisory matches. npm audit, including the test-only axe dependency, found zero vulnerabilities. Version scans do not prove absence of undisclosed vulnerabilities or establish application-level exploitability. Existing Spring/Tomcat/Jackson patch selections remain unchanged.

Source fetching validates the reviewed HTTPS host and every DNS address at connection time, preserves hostname TLS verification, revalidates redirects and limits response size/deadline. New checks reject IPv6 transition, documentation and special-purpose networks, including 6to4/private-IPv4 embedding. [IANA's registry](https://www.iana.org/assignments/iana-ipv6-special-registry/) supports the prefix policy. Ordinary public IPv4/IPv6 addresses remain supported. NAT64 answers fail closed under this deliberately narrow publisher policy; an IPv4-only operator sample was recorded separately without relaxing the application policy.

Security regression checks preserve anonymous/admin/member boundaries, object ownership, authentication-version invalidation, optimistic revisions, same-origin mutation protection, SQL binding, safe errors, import transactions and recovery in disposable isolated databases. The new single-resource admin route also permits administrators to reload paused records without exposing those records through the public route. No production throttling was disabled to make tests pass.

No secrets, private SQL exports, account histories, runtime caches or source-fetch payloads are intended for publication. The final Git index and history are checked separately from the raw ignored evidence directory. No deployment, hosting purchase or database reset is part of this phase.
