# Recom AI catalog and link reliability

Read-only checks cover resource type, active status, category, topic, provider, known/unknown difficulty, language, estimated duration, license, provenance, exact URL duplicates and stored link-check age. [Dimension counts](catalog-quality.json) retain unknown values. The catalog contains 2,365 resources, including 505 articles; no malformed HTTP(S) resource URLs or exact normalized duplicate URL groups were found. Metadata completeness is uneven; unknown difficulty/duration/language are not guessed.

All [105 held edition records](held-edition-review.json) were matched to acquired source identity and reviewed with their license and metadata origin. They remain held: a shared title/provider with a different course identifier does not establish identical syllabus content, and an identifier alone does not prove a pedagogically distinct edition. No resources were automatically merged, imported or discarded to force a zero review queue. No new speculative resources were added in this phase.

Across the whole catalog, stored database observations remain 405 accessible, 105 redirected and 1,855 not checked, including the 200 curated links without imported provenance. The administrator import overview exposes stored counts by imported source (2,165 provenance records); it does not silently assign a provider to curated links. Historical external verification receipts are a separate evidence source; they are not silently written into the original database.

The [combined status summary](link-status-summary.csv) matches all 2,365 exact current URLs to recent prior verification/acquisition receipts and four new sequential approved-source checks. It contains 2,307 accessible/redirected observations, 45 policy-limited, seven restricted and six redirect-policy-limited observations. Original cached timestamps remain visible in the ZIP. These are time-bound observations, not a claim that all URLs were freshly checked in this phase or remain accessible to every reader.

The four fresh checks returned two accessible MedlinePlus pages and two redirected-to-200 MIT pages. Initial dual-stack checks rejected synthesized NAT64 addresses under the hardened source policy; that diagnostic is retained. The explicit IPv4 operator run still applies reviewed-host, actual-connection DNS, TLS, redirect, response and timeout checks. No safety boundary was disabled. Cached results avoid aggressively re-crawling all publishers.

Application maintenance remains disabled by default, incremental (at most ten stale/unverified provenance rows), seven-day cached, serialized by a MySQL advisory lock and paced one second between source requests. Each request has bounded connection/read/deadline/redirect limits. Automatic network retries remain disabled; a later bounded operator run can retry stale observations. This phase does not claim an implemented automatic backoff/retry queue. Restricted/403, authentication, rate-limit and temporary states remain distinct from confirmed not-found. No result automatically pauses a resource or overwrites provider/manual metadata.

This conservative policy leaves some freshness and retry work unresolved. Monitoring should honor provider policy, stop on rate limits, preserve uncertainty and review repeated not-found observations before any administrative action. Full receipts and source attributions are included in the evidence; no full textbook/chapter bodies are published.
