# Evaluation methodology

## A — controlled regression

The seven Phase 3 synthetic category scenarios remain regression tests, rerun by Maven. Their data and conclusions remain labeled synthetic. They are never combined with unrelated genuine data into one accuracy claim.

## B — genuine catalog with editorial judgments

RealCatalogEvaluation builds IDF from the 1,665 genuinely imported new-source metadata records (excluding 105 held editions), and ranks a fully judged fixed pool of 30 resources for seven profiles: Java, DSA, SQL/databases, machine learning, investing/statements, academic communication and visual design/photography. All 210 grades are in catalog-judgments.csv, with original metadata in judged-resource-pool.json. Grade 2 means direct instructional fit, 1 supporting/narrower/advanced fit, 0 unrelated. The Codex assistant assigned grades by reading provider titles/descriptions before running scores. These are not independent human judgments, provider endorsements or user satisfaction labels. Circuits are a distractor for communication skills; photographic Java applets are not Java fundamentals. Labels are not generated by ranking keyword rules.

Both variants use identical genuine candidates, categories, exact/controlled topics and the existing hybrid formula/diversity. The no-history baseline lacks metadata seeds; the extension adds selected-topic cosine. The unchanged eight-point weight is not tuned on qrels. Rankings are restricted to the fully judged pool so unknown labels are not silently treated irrelevant. The pool is deliberately small, topically selected and contains easy negatives; there is no broad statistical generalization claim.

P@K is retrieved grade>0 divided by K; recall divides by all relevant judged resources. Graded DCG uses (2^grade−1)/log2(rank+1), normalized by ideal pool order. MRR uses the first relevant result within K. Coverage is the recommendation-ID union divided by the 30 judged resources, not the 1,770 corpus. Duplicate rate is repeated IDs/list length. Raw per-query results and actual ID/title/grade/point rankings are provided; aggregates are in evaluation-summary.md. A high score is not “100% recommendation accuracy.” Independent assessors and larger pooled judgments remain necessary.

## C — genuine OULAD access histories

OuladEvaluation genuinely downloads UCI OULAD, reads fixed CSV entries without extraction and selects the lowest 1,000 anonymous IDs in CCC/2014B. Train days 0–40; test days 41–80; binary distinct resource access. Negative/later days are excluded. Eligibility requires ≥3 training resources and ≥1 unseen train-known test target. Actual sample: 595 eligible learners, 94 train-known resources, 114,579 scoped rows and 10,655,280 scanned VLE rows.

Both algorithms use the same split, complete unseen train-known candidate sets and stable numeric ties. There is no sampled negative set or randomness. Popularity counts distinct training learners. Item cosine is shared training learners/sqrt(item learner counts), summed across the user's training items. No future access/popularity enters training. Macro P/R/NDCG/MRR/hit rate at 5/10 and recommendation-union coverage are computed on the same learners. Binary NDCG uses held-out access, not grades or satisfaction.

This is one module/presentation and a fixed ID sample. Train-known-only candidates exclude item cold start and change recall's universe; release/exposure affects clicks. A future click is an access proxy, not satisfaction, course acceptance or learning gain. The anonymous VLE activities cannot be mapped to production course IDs. The benchmark therefore remains offline, without learner identities/demographics in exports or app analytics. Results support feasibility only, not deploying an unrelated external item model.

Exact download checksum, split/count manifest, qrels and raw aggregate CSVs make the runs reproducible in Java 21. The raw research ZIP is ignored/excluded. Combined evaluation-results.csv carries explicit dataset/evaluation labels; controlled, editorial and real-interaction experiments remain separate.

Final membership verification compares every judged key with actual MySQL provenance. It caught one database-course edition (MIT 4914) held for duplicate review. The final pool uses the actually imported edition (MIT 4505), with the same direct-fit grade and criteria after reading its provider description; both algorithms were rerun over the same imported-only corpus. Preliminary acquired-pool outputs remain separately labeled acquired-pool-preliminary. The final NDCG@5 is 0.678866→0.885226, rather than the preliminary 0.910753. This correction does not change application code or test fixtures.

The final corpus intentionally isolates newly imported provider metadata; the production corpus can additionally include the 200 older catalog-curated records. Thus this is a declared evaluation subset, not an assertion that the offline IDF/candidate universe exactly reproduces every production feed. data/manifests/imported-resource-keys.json is the actual public source/external-ID membership export. scripts/evaluate-imported-catalog.mjs stages that subset and calls the unchanged Java evaluator; no Node/Python recommendation algorithm replaces Java.
